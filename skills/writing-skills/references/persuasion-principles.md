# Effective Instruction Language

The aim is reliable, appropriate behavior, not compliance with a ritual. Instructions should help the agent make a correct decision in the user's context.

- Use concrete conditions and observable outcomes.
- Explain a non-obvious constraint briefly when that helps it generalize.
- Make important authorization and data-preservation boundaries easy to find.
- Use positive recipes for an output's shape, and clear prohibitions for genuinely disallowed actions.
- Keep conditional exceptions explicit and valid. User and project instructions can legitimately change the default procedure.
- Avoid fabricated urgency, social pressure, guilt, or claims that every alternative is failure.

An announcement or checklist is useful when it helps coordination; neither is a universal prerequisite for ordinary work. A few representative tasks can show whether wording improves decisions. Repeated or independent evaluation is appropriate when uncertainty and impact justify its cost.

Do not infer that persuasive wording proves technical correctness. Review the rule, its scope, and its consequences before making it harder to bypass.
